# H5 · 奶龙版 4 题（独立版本）

一版单独的 16 型测试页面，用来替换线上的 12 题版做一次对照：**4 道题、约 1 分钟、暖米色奶油底**，角色换成 16 张 3D 奶龙。

**原版 `h5/index.html` 一行未动。** 两版可以同时部署、同时存在，互不干扰。

---

## 一、文件

```
h5_奶蛙版4题/
├── index.html          单文件页面（HTML + CSS + JS 全在里面，无外部依赖）
├── assets/             16 张角色图，文件名 = 小写类型代号
│   ├── dtro.jpg … nbph.jpg     720×830，合计 0.84 MB
└── README.md           本文件
```

页面只依赖 `assets/` 里的本地图，不加载任何 CDN、字体或第三方脚本。

## 二、怎么测

4 道题，**每个维度只出 1 题**：

| 题号 | 维度 | 对应原版第几题 |
|---|---|---|
| 第 1 题 | 数据驱动 D ↔ 直觉判断 N | 原版 Q1 |
| 第 2 题 | 善用现成 T ↔ 偏好自研 B | 原版 Q4 |
| 第 3 题 | 复用优先 R ↔ 开荒优先 P | 原版 Q7 |
| 第 4 题 | 擅长编排 O ↔ 专注攻坚 H | 原版 Q10 |

每维 1 题、二选一，**没有平票**，1 题定该维的一极，4 题拼成 4 位代号。

> ⚠ 代码里 `computeCode()` 的判定阈值是 `>= 1`（不是原版的 `>= 2`）。原版每维 3 题、两极互补合计恒为 3，所以用 `>= 2`；本版每维只有 1 题，计数最大为 1，**照抄 `>= 2` 会永远输出 `NBPH`**。这是唯一会静默出错的改动，改的时候务必一起改。

## 三、和 12 题版的差别

| | 12 题版 `h5/` | 4 题版 `h5_奶蛙版4题/` |
|---|---|---|
| 题量 / 用时 | 12 题 / 约 2 分钟 | 4 题 / 约 1 分钟 |
| 视觉 | 直角、硬投影、荧光绿强调色 | 圆角、软阴影、暖米色、橙棕渐变按钮 |
| 角色图 | 16 张扁平插画（`cards/`） | 16 张 3D 奶龙（`assets/`） |
| 进度存储 | `ai_profile_progress_v1` / `ai_profile_type_v1` | `nw_progress_v1` / `nw_type_v1` |
| 结论精度 | 每维 3 题多数决 | 每维 1 题，噪声更大 |

因为两版的 localStorage 键不同，同一个人在同一台设备上测过 12 题版，再打开 4 题版不会被上一版的结果带跑。

**4 题版是自我叙事模板，不是心理测量工具。** 页面上的免责文案已经写明这一点，对外传播时不要称它「准确」「科学测评」。

## 四、怎么部署

### 路线 A：跟现有 GitHub Pages 放一起（推荐）

仓库还是 `https://github.com/daionggelin/mbti_like`，现有站点是 `https://daionggelin.github.io/mbti_like/`。

1. 把 `h5_奶蛙版4题/` 整个文件夹上传到该仓库根目录，**文件夹名改成 `naidong`**（中文名在 URL 里会被转义成很长的百分号串，不方便贴进视频和评论）。
2. 等 1–2 分钟 Pages 构建，访问 `https://daionggelin.github.io/mbti_like/naidong/`。
3. 手机上打开确认：图能出来、4 题能答完、结果页出码正确、注册按钮能跳。

### 路线 B：本地先看

`index.html` 是纯静态页，双击就能打开。唯一要注意的是：用 `file://` 打开时 localStorage 能用，但部分浏览器对本地文件限制较严；想更接近线上行为，起一个静态服务器再访问：

```powershell
python -m http.server 8080
# 然后浏览器打开 http://localhost:8080/h5_奶蛙版4题/
```

## 五、改之前必须知道的几件事

**1. 图不要重新裁。** 源图 954×1100 底部有「千问AI生成」水印。页面用 `.photo{aspect-ratio:720/790}` + `object-fit:cover; object-position:50% 0%` 把它裁在可视区外——**角色脚底在源图 y≈1030，水印在 y≈1045 以下**，动这个比例很容易切到脚。图由 `tools/prep_naidong_images.py` 统一生成，重跑请用脚本，不要手工另存。

**2. 水印不能抠。** 16 张里有 5 张（DTRO / DBRH / NBRH / DTPO / NBPO）水印正压在深色机器道具上，键控或插值都会在道具上留下假色斑。这条已经试过并回滚。

**3. 改完跑一遍校验：**

```powershell
node tools/check_h5_naidong.mjs
```

73 项检查，覆盖文件与链接、页面结构、占位符、**计分逻辑（把 `<script>` 在打桩环境里真跑一遍，16 种作答组合逐个验证）**、16 张图的尺寸与体积、图片与卡片的接缝处理、以及「原版 h5 未被改动」。退出码 0 才算通过。

## 五之二、图片和卡片之间那条边是怎么处理掉的

源图是 954×1100 的灰底影棚图，底色约 `#D5D4D0`；卡片是 `#FFFCF7`。两者明度差 30 多级，直接并排会看到一条硬边。

试过但**没有采用**的两条路，记在这里免得再走一遍：

- **把灰底重着色成奶油色**（从画面四边 flood fill 只吃「亮且不饱和」的像素）。背景是能换掉，但角色身体周围会留一圈灰晕，个别图顶部还有未填满的灰块（原图顶边本身带一层柔和暗角，生长会在那里断掉）。要修得逐张调参，不划算。
- **在照片下面接一段固定颜色的渐变**。16 张图的下沿颜色从 `#423E39`（深色机器贴着边）到 `#EBEAE8` 不等，没有任何一个固定颜色能对上，接上去反而多一条更显眼的横线。

最后用的是**版式**解决，不动素材：

1. 结果页卡片去掉内边距，照片铺满卡片顶部 —— 上、左、右三条边直接和卡片边界重合，没有第四道边；
2. 正文放进 `.sheet`：半透明奶油渐变 + `backdrop-filter:blur(12px)`，`margin-top:-46px` 压在照片下沿上。照片下边缘被这层奶油盖住，接缝落在毛玻璃里；
3. 渐变用固定 px 收口（`0 → 70px → 118px` 就到纯色），保证标题、金句这些字一定落在实色上，不受底下照片深浅影响；
4. 封面那 4 张缩略图保留画框样式，把 `filter` 的 `brightness` 提到 `1.10`、`sepia` 提到 `.16`，让灰底往奶油色靠近（缩略图面积小，这样够了）。

改这几处时注意：`.sheet` 的圆角是 24px、照片所在卡片是 `overflow:hidden`，动错层级会让照片从卡片圆角里露出来。
